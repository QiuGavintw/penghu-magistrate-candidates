- 現象：PowerShell 輸出資料夾名稱與 Python 訊息時出現「���jNPU」等亂碼。

  舊的 host 設定或 keyring 顯示快取。由於 repo 建立與 push 權限取決於
  Token 實際身份，先以 gh api user 驗證為 QiuGavintw，且具 repo 權限。
- 處理：不更動既有登入設定，避免影響其他專案；建立 Repository 前

四、第三階段：候選人資料擷取
------------------------------------------------------------------------

【4-1 擷取程式設計】

模組分工：

- scraper/config.py：來源網址、UA、重試次數、請求間隔、輸出路徑
- scraper/fetch.py：GET、重試、429/5xx 退避、可選本機快取
- scraper/parse.py：總覽頁、候選人頁、政見列表頁、政見明細頁解析
- scraper/build.py：正規化、完整度計算、JSON/CSV 輸出、錯誤隔離
- scraper/report.py：由資料集自動產生 sources.md

資料規則落實方式：

- 所有找不到的欄位回傳 None，不猜測。
- 政見明細頁失敗時，退回列表頁摘要，並在 errors 記錄。
- 單一候選人失敗時，仍由總覽頁建立基本資料，其他候選人不受影響。
- 每項政見保留原始新聞／政黨新聞稿網址、段落、發布日期、查閱日期。

【4-2 開發問題與解決】

問題 C：環境缺少 requests、beautifulsoup4、pytest
- 分析：系統 Python 為乾淨環境。
- 解決：在專案內建立 .venv，安裝 requests 2.34.2、
  beautifulsoup4 4.15.0、pytest 9.2.0，並建立 requirements.txt。
- 結果：可重現的本地開發環境。

問題 D：誤設所有政見的 content_type 都是「新聞彙整摘要」
- 現象：測試失敗，實際資料出現 6 筆「候選人公開自述」。
- 分析：網站會依來源類型標記不同證據等級，不能一律視為新聞摘要。
- 解決：保留網站原始標籤，不自行統一；測試改為允許
  「新聞彙整摘要」與「候選人公開自述」兩種值。
- 結果：17 筆新聞彙整摘要、6 筆候選人公開自述，全部如實保留。

問題 E：星座欄位解析為 None
- 現象：單元測試失敗。
- 分析：解析器把 selector 限定在 details.birthday-evidence 內，
  但測試 fixture 與部分頁面的星座標記在人物標頭。
- 解決：改為讀取 main 內第一個 span.person-zodiac，並移除符號，
  只保留中文星座名稱。
- 結果：6 位候選人星座皆正確；此欄位僅供參考，不用於分析。

問題 F：政見總數宣告值解析為 None
- 現象：/policies 頁的「N 項已收錄主張」抓不到。
- 分析：原本只取 .policy-catalog-heading 的第一個 p，
  但第一個 p 是「POLICIES / 2026」。
- 解決：改為逐一檢查該區塊所有 p，找到含「項已收錄主張」者。
- 結果：每位候選人宣告數與實際卡片數一致。

問題 G：Windows 主控台輸出中文亂碼
- 已在第一階段處理；程式與檔案一律以 UTF-8 寫入。
- 驗收時以 Python 讀回檔案檢查，確認無 U+FFFD 取代字元。
